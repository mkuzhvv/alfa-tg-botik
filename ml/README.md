# Локальный RAG Альфа-Курса

Подготовка предоставленного корпуса, поиск и консультации через локальную Ollama.
Telegram и выполнение пользовательских действий остаются задачей Java-бэкенда.

[Инструкция для бэкендера](../docs/RAG_BACKEND_INTEGRATION.md): готовый
`rag_bridge.py` обменивается UTF-8 JSON Lines через stdin/stdout и держит индекс
в памяти процесса. Java остаётся владельцем API и состояния пользователей.

## Запуск

Python 3.11+, Ollama с локальными `embeddinggemma:300m` и
`qwen3.5:9b-q4_K_M`. Команды выполняются из корня проекта:

```sh
uv venv .venv
uv pip install --python .venv/bin/python -r ml/requirements.lock
.venv/bin/python ml/setup_local.py data/drive-download-20261113T183742Z-1-001.zip
.venv/bin/python ml/rag.py chat data/processed/2026-11-13-local
```

Без uv: `python3 -m venv .venv`, затем
`.venv/bin/python -m pip install -r ml/requirements.lock`.
Первый setup скачивает недостающие веса и tokenizer Qwen, импортирует данные,
готовит корпус и строит индекс. Повторный setup проверяет происхождение данных
и использует существующий индекс. Незавершённая индексация продолжается.
Новый архив или embedding-модель требуют новой `--version`.

В чате: `/sources` — исходные полные фрагменты последних ссылок,
`/reset` — очистить историю, `/quit` — выход. История хранится только в памяти.
Тестовый профиль кофейни подключается через `--context ml/demo_context.json`.

```sh
.venv/bin/python ml/rag.py ask data/processed/2026-11-13-local 'Зачем малому бизнесу CRM?'
.venv/bin/python ml/rag.py retrieve data/processed/2026-11-13-local 'Как удерживать покупателей?'
```

## Текущая конфигурация

- EmbeddingGemma 300M, размерность 768. Существующий индекс совместим с новым поиском.
- Поиск `hybrid_dense`: BM25 с русским Snowball-стеммингом и векторный поиск;
  RRF с весом векторного ранга 0.75, константой 60 и окном 100 кандидатов.
- Косинусный порог 0.35, до двух фрагментов одного материала в топ-5.
  Косинус и RRF имеют разные шкалы: RRF не используется как вероятность.
- Три полных фрагмента передаются Qwen. Окно 16384, выход до 1200 токенов,
  общий бюджет консультации 60 секунд, chat batch 512.
- Tokenizer Qwen считает бюджет локально; остаётся резерв 1024 токена на оболочку.
  Если tokenizer недоступен или выбрана другая семья модели, используется
  консервативная оценка по байтам UTF-8. Тексты оставшихся источников не режутся
  в конфигурации по умолчанию. Старые сообщения и слабые карточки удаляются раньше.
- Основной режим `extracts`: модель выбирает до двух ID готовых выдержек;
  программа подставляет их текст и проверяет происхождение. Основной ответ —
  до 900 символов. Это более строгий, извлекающий режим, с ограничением свободного
  пересказа и персонализации. Правильность выбора выдержки не гарантируется.
- Публичный контракт сохранён: ANSWER / CLARIFY / NOT_FOUND, ссылки достраиваются
  из каталога; `profilePatch={}`, `planProposal=null`, `reminderProposal=null`.
- Общий неопределённый запрос получает уточнение. Команда изменения профиля,
  плана или напоминания получает явное сообщение, что действие не выполнено.
  При отсутствии фрагментов возвращается NOT_FOUND без вызова генерации;
  сбой embedding/API остаётся технической ошибкой.

При прямом подключении Ollama из Java нужен адаптер нового внутреннего формата:
он создаёт passages/E-ID, проверяет выбор модели и достраивает публичный ответ.
Одного переноса промпта в старый парсер compact-1 недостаточно. Python `ask`
уже выполняет это преобразование и возвращает прежние публичные поля.

Дополнительно поддержан расчёт точки безубыточности одной товарной позиции по
явно указанным постоянным расходам за период, цене и переменным расходам на единицу.
Формула проверяется в корпусе; вычисления выполняются через Decimal с округлением
количества вверх. При неполных/неоднозначных данных задаётся уточнение. Это отдельный
ограниченный калькулятор, а не универсальная арифметика или финансовая модель.

Настройки выбраны на dev-наборе. Порог не является универсально откалиброванной
уверенностью модели; `thresholdCalibrated=false` сохраняется.

Для экспериментов `ask/chat` поддерживают `--answer-mode generative|evidence|extracts`,
`--compression none|window`, `--strategy dense|bm25|hybrid|hybrid_dense`,
`--max-per-material`, `--min-score`, `--rerank` и `--timeout`.
`generative` сохраняет свободный компактный ответ старого формата;
`evidence` просит модель переписывать дословные цитаты и проверяет их.
`--rerank` — экспериментальный локальный LLM-reranker; ошибки отображаются
в диагностике, после них используется исходный порядок. Он выключен по умолчанию.
Для точного воспроизведения исходной реализации используется её сохранённый
снимок runtime, а не только переключение `--strategy dense`.

## Данные и подготовка

По предоставленному архиву: 1116 карточек, 3761 фрагмент, всего 4877 векторов.
Импорт без Docker не исполняет SQL из дампа, выбирает только таблицы и поля
из `rag.TABLES`, проверяет COPY-схему и преобразует boolean/числа/даты.
Пользовательские таблицы не входят в снимок. ZIP извлекается без использования
вложенных путей его файлов. Существующий снимок не перезаписывается.

```sh
.venv/bin/python ml/rag.py import-backup data/drive-download-20261113T183742Z-1-001.zip
.venv/bin/python ml/rag.py prepare --version my-v3
.venv/bin/python ml/rag.py validate data/processed/my-v3
.venv/bin/python ml/rag.py index data/processed/my-v3 --batch-size 16
```

`import-backup` принимает ZIP с единственным `.backup` или сам PGDMP-файл;
`--output` должен находиться внутри `data/source/`.
`setup_local.py --data-only` готовит корпус; `--retrieval-only` — ещё и индекс,
без загрузки генеративной модели. Альтернатива импорту — `rag.py export` из
уже восстановленной `alfa_source` через Docker Compose, в согласованной READ ONLY
транзакции. Восстановление БД само по себе скрипт export не выполняет.

Артефакты версии: `materials.jsonl`, `chunks.jsonl`, `manifest.json`, `report.json`,
после индексации — `semantic.sqlite`. Хеши корпуса и digest модели проверяются.
При смене embedding-модели нужен новый индекс; смешивать пространства нельзя.
EmbeddingGemma использует `title: ... | text: ...` и
`task: search result | query: ...`. Для поддержанного `qwen3-embedding:0.6b`
используется другой query-prefix; сравнение качества этой модели не проводилось.

## Доступ к содержимому

Публикация проверяется по справочнику статусов, доступности сущности и её связей.
Для статей требуется `IsPublic=true`. Закрытые, удалённые, будущие и неоднозначные
материалы исключаются. `Courses.Cost=null` означает бесплатный курс; публикация,
тип курса, тарифы и подписки проверяются отдельно. Урок допускается только при
подтверждённом доступе ко всем его активным родительским связям и группам.
Платный курс может попасть в каталог рекомендаций по описанию, но не в тексты ответа.

Используются наблюдавшиеся ссылки, адреса не придумываются. В текущем корпусе
522 записи исключены из-за неподтверждённого URL. Урок ссылается на родительский курс.
Видео, аудио, файлы, картинки и тесты не транскрибируются. HTML очищается от
исполняемых блоков, фрагменты режутся по абзацам и предложениям, дубликаты удаляются.
Актуальность законодательства из старого источника автоматически не подтверждается.

Исходные данные, корпус, eval-набор и отчёты хранятся в игнорируемых `data/source/`
и `data/processed/`; ZIP также игнорируется. Не публикуйте их в открытом репозитории.
Все разрешения внешней передачи остаются false. Runtime запрещает удалённую Ollama,
прокси, перенаправления и облачные модели. Внешняя загрузка tokenizer/весов
не отправляет корпус; во время консультаций используются локальные модели.

## Валидация

[Методика, команды и ограничения оценки](EVALUATION.md).
Стартовый набор: `data/source/evaluation-2026-11-14/`, 100 примеров, 69 dev / 31 test.
Результаты и снимок исходного runtime:
`data/processed/evaluation-2026-11-14/`. Итог формируется в `REPORT.md` и `summary.json`.

```sh
.venv/bin/python -m unittest discover -s ml -p 'test_*.py'
.venv/bin/python ml/rag_eval.py data/processed/2026-11-13-local data/source/evaluation-2026-11-14/test.jsonl --mode generation --strategy hybrid_dense --min-score 0.35 --max-per-material 2 --answer-mode extracts --output data/processed/my-evaluation.json
```

Этот повторный прогон не участвует в выборе уже зафиксированных параметров.
Шесть старых smoke-вопросов и ручной прогон десяти вопросов сохранены отдельно;
они не считаются независимой оценкой качества.
