# Оценка RAG

## Набор и границы применимости

100 агентских синтетических примеров, составленных по предоставленным источникам:
60 предметных вопросов, 10 неопределённых, 10 вне базы, 10 команд действий и
10 проверок устойчивости. Предметные примеры охватывают 20 семейств источников.
В test — 22 предметных/устойчивых вопроса по шести семействам источников и
9 вопросов на уточнение, отказ и действия. Разделение 69 dev / 31 test сделано по семействам: парафразы одного вопроса
и вопросы одного материала не попадают в обе части. Корпус поиска остаётся полным.

Для ANSWER заданы релевантные материалы/фрагменты, дословная эталонная цитата,
обязательные понятия и контекст. Цитаты проверяются программой на наличие в
разрешённом источнике. Это не независимая экспертная разметка; альтернативные
подходящие фрагменты могут быть размечены неполно. Много вопросов — определения
и объяснения; выборка недостаточна для обещаний о всех реальных диалогах,
арифметических расчётах, актуальности законов и сложных бизнес-рекомендациях.

В manifest сохранены хеши файлов. Оценщик проверяет обе части, их размеры,
непересечение групп, наличие цитат и права доступа. Изменение набора после
фиксации обнаруживается. Для исправленной разметки нужна новая версия manifest
и новый независимый контрольный набор, если старый test уже использован для настройки.

## Что измеряется

- Material Hit@5: найден ли один из размеченных материалов.
- Chunk Hit/Recall@5 и MRR@5: найден ли конкретный фрагмент и насколько высоко.
- Sent reference evidence: присутствует ли эталонная цитата в реально отправленном
  тексте, а не просто в правильной статье. После компрессии учитывается именно окно.
- Status accuracy и разбивка по типам: ANSWER / CLARIFY / NOT_FOUND.
- Честная обработка неподдержанных действий: route=unsupported_action,
  отсутствие предложений выполнения и изменений состояния.
- Технические ошибки, p50/p95. Сбой остаётся в знаменателях метрик.
- Concept coverage proxy: буквальное присутствие размеченных основ слов.
  Это вспомогательная проверка полноты, не semantic correctness и не faithfulness.
- Повторный аудит извлечённых ответов: текст и ссылки восстанавливаются из
  выбранных E-ID и реально переданных источников; проверяется отсутствие платных
  фрагментов. Дословность не гарантирует уместность выдержки или истину источника.

Объяснение рекомендации и уточнение не являются дословными выдержками.
Автоматическая проверка фактической обоснованности всего свободного текста
не заявляется. LLM-судья той же Qwen не используется как эталон качества.
Принципы разделения метрик: [Ragas](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/).

## Эксперименты

Снимок исходного runtime сохранён до правок. На dev сравнены 32 конфигурации:
векторный поиск, BM25 с семантическим порогом, два веса RRF, четыре косинусных
порога, один или два фрагмента на материал. Шкалы косинуса, BM25 и RRF не смешиваются.
[Определение RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion).

Критерий выбора записан в sweep: 0.6 доли переданных эталонных цитат +
0.25 Chunk Hit@5 + 0.15 MRR@5 − 0.15 доли внебазовых вопросов с кандидатами.
Это локально выбранный критерий, не универсальный стандарт качества.

Проверены свободная генерация, переписывание дословных цитат с проверкой и
выбор идентификаторов заранее подготовленных выдержек. Пилоты с полным контекстом
из пяти фрагментов, короткими окнами и batch 2048 сохранены со всеми завершёнными
запросами и ошибками. Неудачные варианты прерывались и не выдаются за полные прогоны.
Полный выбор выдержек по трём источникам проверен на 14 предметных dev-вопросах.

Локальный LLM-reranker проверен на трёх dev-примерах: он добавил задержку,
один раз потребовал fallback после тайм-аута, в другом случае опустил эталонный
фрагмент на пятую позицию. По умолчанию выключен. Сжатие окна выбрасывало
эталонные цитаты и также выключено. Oracle-диагностика отдельно подаёт
эталонный фрагмент вместо поиска; её метрики не являются результатом системы.

До финальной оценки сохранён freeze.json с выбранными настройками, хешами кода,
зависимостей и manifest набора. Финальный test не используется для подбора.
Результаты конкретного прогона находятся в локальном REPORT.md; методика
не подменяет результаты заранее заданными обещаниями.

## Повторение

```sh
# Поиск без генерации
.venv/bin/python ml/rag_eval.py data/processed/2026-11-13-local data/source/evaluation-2026-11-14/dev.jsonl --mode retrieval --strategy hybrid_dense --min-score 0.35 --max-per-material 2 --answer-mode extracts --output data/processed/retrieval-run.json

# Подбор только на dev: файл с test-примерами отклоняется
.venv/bin/python ml/retrieval_sweep.py data/processed/2026-11-13-local data/source/evaluation-2026-11-14/dev.jsonl --output data/processed/sweep-run.json

# Полный диалоговый ответ на каждый пример
.venv/bin/python ml/rag_eval.py data/processed/2026-11-13-local data/source/evaluation-2026-11-14/test.jsonl --mode generation --strategy hybrid_dense --min-score 0.35 --max-per-material 2 --answer-mode extracts --output data/processed/generation-run.json
```

`--one-per-group` и `--limit` предназначены для пилотов; их результаты нельзя
выдавать за полный набор. `--oracle` — только диагностика с золотым контекстом.
`--runtime PATH` позволяет оценить снимок исходного runtime.
`--resume` продолжает файл только при совпадении кода, моделей, индекса,
набора, выбранных ID и параметров. Ошибки уже завершённых запросов автоматически
не переигрываются. Генерация не кэшируется; query embeddings кэшируются локально
с ключом, включающим digest весов. Время с этим кэшем не равно холодному запуску.

Для следующего этапа нужны реальные обезличенные вопросы, независимая ручная
проверка обязательных фактов и калибровка по бизнес-сценариям. После подбора по
текущему test он должен считаться dev; для новой честной оценки нужен новый test.

## Дополнительная регрессия после бенчмарка

Живой тест с новыми числами выявил, что извлекающий режим может показать пример
из статьи вместо вычисления ответа. Добавлен отдельно проверенный Decimal-калькулятор
точки безубыточности одной позиции. Его входная ветка не активна на всех 100
оценённых вопросах. Основные результаты сохранены для scored_runtime.py;
послебенчмарковая правка, её хеши и отдельные проверки описаны в REPORT.md/release.json.
Этот случай показывает, почему высокий статусный скор и дословность не заменяют
проверку полезности ответа на новых сценариях.
