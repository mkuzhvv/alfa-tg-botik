# Альфа-Курс: Telegram Mini App

Три экрана: план, напоминания и профиль. React/TypeScript/Vite, Zustand,
TanStack Router, Tailwind и Vaul. Оформление экранов взято из ветки frontend.
Приложение использует реальные данные Java API; демонстрационного режима нет.

## Запуск с Docker

Из корня проекта:

```shell
docker compose up -d --build
```

Интерфейс доступен на `http://localhost:8081`, порт задаётся `FRONTEND_PORT`.
Nginx отдаёт интерфейс и передаёт `/api/v1` в backend:8080. Профиль и прочие
вложенные маршруты открываются напрямую. API и интерфейс используют один адрес,
поэтому отдельное разрешение CORS не требуется. Секреты бота во frontend не передаются.

Для открытия внутри Telegram нужен HTTPS-адрес. Временную ссылку без регистрации
можно получить через [localhost.run](https://localhost.run/docs/). Нужен SSH-клиент
(в современных Windows, macOS и Linux он обычно уже установлен):

```shell
ssh -T -o IdentityAgent=none -o IdentitiesOnly=yes -o IdentityFile=none -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes -R 80:127.0.0.1:8081 nokey@localhost.run
```

При первом подключении SSH запросит подтверждение ключа сервера. Аккаунт и личный
SSH-ключ для `nokey` не нужны. Команда выведет HTTPS-адрес, ведущий к локальному nginx.
На проверенном компьютере этот способ работает при включённом Happ TUN; менять VPN
или системный DNS не требуется.

Полученную HTTPS-ссылку укажите в корневом `.env` как `TELEGRAM_MINI_APP_URL`,
затем выполните `docker compose up -d --no-deps --wait backend`. При запуске Java зарегистрирует
кнопку «Мой бизнес» в меню бота. Временный адрес зависит от работающего процесса
туннеля и периодически меняется у бесплатного сервиса; после его смены обновите
настройку и контейнер backend. Пока нужна ссылка, компьютер, контейнеры и SSH должны
работать. Для остановки команды в терминале нажмите Ctrl+C. Базы и Ollama через
туннель не публикуются.

Альтернатива — `cloudflared tunnel --url http://127.0.0.1:8081`. Если VPN мешает
служебным DNS-записям или соединению Cloudflare, используйте SSH-вариант выше.

## Локальная разработка

Нужны Node.js 24 и npm. В папке frontend:

```shell
npm ci
npm run dev
```

Vite принимает локальные запросы на 5173 и проксирует `/api` в localhost:8080.
Обычный браузер без Telegram показывает приглашение открыть приложение из бота.
Подмена пользователя dev-заголовком не поддерживается. Для отдельного адреса API
есть `VITE_API_BASE_URL`; для обычной сборки используется относительный `/api/v1`.
Имя бота задаётся публичной настройкой `VITE_BOT_USERNAME`, в Docker —
`TELEGRAM_BOT_USERNAME`. Токен бота сюда добавлять не нужно.

## Вход и изменения

При открытии отправляется подписанный Telegram initData. Только после успешного
входа загружаются пользователь, план и напоминания. Сессионный токен хранится в
памяти. При 401 выполняется одна попытка повторного входа и повтор исходного
запроса с тем же телом и ключом. Просроченный initData требует закрыть и заново
открыть приложение. Выход отзывает сессию и очищает состояние экранов.

Изменения применяются на экране после успешного ответа API. Ошибки не заменяются
демонстрационными данными. Повтор создания после потери связи использует прежний
Idempotency-Key, пока тело команды не изменилось. 409 показывает необходимость
перечитать данные; версия берётся из показанной пользователю записи. Профиль
сохраняет черновик при внешнем изменении и предлагает загрузить актуальные поля.
Обновление профиля не изменяет сохранённый план.

Кнопка генерации открывает форму цели. Для действующего плана требуется отдельное
подтверждение замены; прежний план остаётся до успешного ответа Java. В напоминаниях
доступны четыре типа расписаний, редактирование, пауза, возобновление и отмена.
Зона подтверждается пользователем; локальная дата/время ONCE переводятся в UTC.
Правила перехода времени соответствуют серверу: сдвиг вперёд при пропуске и первое
вхождение при повторе. Число MONTHLY — 1–31. Ближайшую отправку возвращает сервер.
Завершённые записи доступны только для чтения.

Данные обновляются при возвращении в окно и кнопкой «Обновить данные».
Пустые поля профиля можно очистить; неизвестные значения передаются как null.
Налоговый шаблон открывает обычную форму: сроки не вычисляются автоматически.

## Проверки

```shell
npm run build
npm run lint
npm test
```

Тесты проверяют порядок авторизации, API, повторы, ошибки, версии и часовые пояса.
Для браузерной проверки нужны запущенные контейнеры, каталог и локальная Ollama:

```shell
npx playwright install chromium
npm run test:e2e
```

На Windows с установленным Edge можно задать `PLAYWRIGHT_CHANNEL=msedge`.
Адрес проверки задаётся `MINI_APP_TEST_URL`, по умолчанию localhost:8081.
Токен для подписи тестового initData читается из окружения или корневого `.env`.
Браузерный тест создаёт отдельного временного пользователя с тестовым Telegram ID;
фактический SDK Telegram в этом тесте заменён локальной имитацией. Java проверяет
настоящую подпись, а API и генерация плана работают в реальном приложении.
Напоминания теста назначаются в будущее, отменяются перед очисткой, затем удаляется
только его пользователь. Рабочие пользовательские данные тест не изменяет.
Снимки ширин 360/768/1280 сохраняются локально в игнорируемом data/source.
Настоящее открытие и обмен с ботом дополнительно проверяются в Telegram.

Генерация типов API: `npm run gen:api`. Источник — docs/contracts/backend.openapi.yaml.
