## Общие форматы

- HTTP API: `/api/v1`, JSON, имена полей `camelCase`.
- Идентификаторы приложения: UUID-строки. Текущего пользователя определяет сервер.
- Моменты времени: UTC с `Z`. Локальное время: `HH:mm`, дата: `YYYY-MM-DD`, зона: IANA, например `Europe/Moscow`.
- Неизвестное значение: `null`. В PATCH пропущенное поле не меняется, явный `null` очищает nullable-поле.
- Неизвестные поля и неверные типы отклоняются. Строка не превращается в число автоматически.
- Ответы — plain text. Разметку Telegram экранирует бэкенд; фронтенд не вставляет текст как HTML.
- Ошибка: HTTP `application/problem+json`, поля `type`, `title`, `status`, `code`, `requestId`, `instance`; при ошибках полей — `errors` со списком `field`, `code`, `message`.
- Чужой или недоступный объект возвращает `404`. `X-Request-Id` связывает HTTP-ответ с логами.

## Изменения и повторы

Профиль, план и напоминание имеют версию. Изменение передаёт `expectedVersion`. Несовпадение даёт `409 VERSION_CONFLICT`: фронтенд перечитывает объект, а не затирает чужое изменение. Изменение шага увеличивает версию всего плана.

Создание напоминания требует UUID-заголовок `Idempotency-Key`. Сетевой повтор одной команды использует тот же ключ. Тот же пользователь, ключ и тело возвращают прежний результат; другое тело даёт `409 IDEMPOTENCY_CONFLICT`. Область ключа — пользователь и операция, срок хранения — минимум 24 часа. Незавершённая команда даёт `409 REQUEST_IN_PROGRESS`.

Повтор Telegram `update_id` не выполняет действие повторно. Кнопка с предложением проверяет владельца, срок и состояние; повтор подтверждения возвращает первоначальный результат.
