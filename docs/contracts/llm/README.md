# Контракт ML 2 и бэкенда

Версия 0.1.0. ML 2 передаёт модель, способ запуска, инструкции, параметры и результаты проверки качества. Java вызывает модель через Spring AI. Прямого API модели для фронтенда нет.

## Вход модели

| Поле | Тип и смысл |
|---|---|
| `schemaVersion` | Строка `0.1.0` |
| `now` | Текущее время UTC от сервера |
| `message` | Сообщение пользователя до 4000 символов |
| `profile` | Известные поля Profile из контракта фронтенда |
| `history` | Массив объектов `role: USER или ASSISTANT`, `text: string`; не более 12 сообщений |
| `sources` | До 8 объектов: `chunkId`, `materialId`, `title`, `text` |
| `catalog` | До 12 карточек с полями `id`, `title`, `kind`, `description`, `isPaid`, `duration`, `url` |
| `currentPlan` | Текущий Plan или null. Карточки материалов шагов имеют тот же набор полей, что в `catalog` |

Модель получает только необходимые разрешённые сведения. Telegram ID, токены и чужие профили не передаются. До внешнего API бэкенд удаляет персональные данные и фильтрует контент по разрешениям. Если корректно подготовить запрос нельзя, применяется локальная обработка или понятное сообщение об ограничении.

Количество сообщений и фрагментов — верхняя граница. Фактический контекст укладывается в бюджет выбранной модели. Тексты источников и пользователя не могут отменять системные правила или разрешать операции.

## Ответ модели

Модель возвращает один JSON-объект без Markdown-обёртки. Все поля присутствуют.

| Поле | Тип и смысл |
|---|---|
| `schemaVersion` | Строка `0.1.0` |
| `status` | ANSWER, CLARIFY, NOT_FOUND, ACTION_PROPOSAL |
| `answer` | Русский plain text, 1–2500 символов |
| `sourceChunkIds` | Массив использованных chunkId только из входных sources |
| `recommendations` | До трёх объектов `materialId: UUID`, `reason: string до 300 символов`; ID берётся из входного catalog |
| `profilePatch` | Объект явно сообщённых новых полей Profile; без изменений пустой |
| `planProposal` | Объект предложения плана или null |
| `reminderProposal` | Объект предложения напоминания или null |

`planProposal`: `goal` до 250 символов и `steps` из трёх–пяти объектов. Каждый шаг содержит `title` до 160, `description` до 600 и `materialIds` из одного–двух доступных материалов.

`reminderProposal`: `title` до 160, `schedule` по контракту фронтенда, nullable `materialId` и `planStepId`. Поддерживаемые варианты `schedule.type` — `ONCE`, `DAILY`, `WEEKLY`, `MONTHLY`. Связанный шаг берётся только из текущего плана.

## Поведение

| Статус | Требование |
|---|---|
| ANSWER | Полезный ответ по источникам; минимум один sourceChunkId. Допускается предложение плана; reminderProposal=null |
| CLARIFY | Один конкретный уточняющий вопрос; источники пусты, оба предложения=null |
| NOT_FOUND | Честно обозначен пробел; источники пусты, оба предложения=null. Можно рекомендовать близкий материал с объяснением ограничения |
| ACTION_PROPOSAL | Полностью определённое напоминание: reminderProposal заполнен, planProposal=null |

Для напоминания с неизвестными датой, временем или подтверждённой зоной используется CLARIFY. «Завтра» определяется по `now` и зоне пользователя. План и напоминание одновременно не предлагаются.

Модель не возвращает URL, цену, SQL или утверждение, что действие уже выполнено. Неизвестные факты о бизнесе не придумываются. Явно сообщённые поля можно предложить в profilePatch; догадки уточняются. Известные значения не стираются null без просьбы пользователя.

## Граница ответственности

ML 2 отвечает за инструкции, полезность, обоснованность, персонализацию и корректную реакцию на пробелы. Ссылка на источник сама по себе не доказывает корректность текста.

Java проверяет структуру, допустимость ID, принадлежность шага, расписание и права. Карточки и ссылки строятся по серверному каталогу. План и напоминание сохраняются только после явного подтверждения пользователя. Предложение плана хранится 24 часа; замена активного плана требует отдельного подтверждения.

Для `/plans/generate` Java передаёт выбранную цель в `message` и использует инструкцию на построение плана. Для успешной генерации нужен `ANSWER` с заполненным `planProposal`. `CLARIFY` возвращает уточнение цели, `NOT_FOUND` — сообщение о нехватке материалов по правилам контракта фронтенда. В этой операции Java сохраняет план и пояснения из `recommendations` для связанных материалов. Формат входа и ответа модели общий с консультацией.

Общий бюджет консультации — 60 секунд. Допускается одно исправление неверного формата в пределах того же бюджета. Повторная ошибка, тайм-аут или недоступность модели дают техническое сообщение, а не NOT_FOUND. Расписания продолжают работать независимо от модели.

ML 2 проверяет известные темы, отсутствие ответа, неоднозначность, пустой профиль, продолжение диалога, платные рекомендации, запрос закрытого текста и создание напоминаний. Версии инструкций и модели фиксируются, изменения проверяются до передачи в бэкенд.
