# Запуск и работа с проектом

Все команды выполняются из корня репозитория, если не указано другое.
Основной путь одинаков для Windows, macOS и Linux: Docker запускает PostgreSQL,
Java и nginx; Ollama с моделями работает на компьютере. Нативные Java, Maven,
Node.js и Python при наличии готового пакета материалов не нужны.

## 1. Что установить и получить

| Что | Для чего |
|---|---|
| Git | Клонирование репозитория |
| Docker с Linux-контейнерами и Compose v2 | PostgreSQL, backend и frontend |
| [Ollama](https://ollama.com/download) | Локальные embedding- и chat-модели |
| Подготовленный пакет от команды либо банковский `.backup` | Материалы для поиска и консультаций |
| Telegram и токен собственного бота от `@BotFather` | Чат и авторизация Mini App |
| SSH-клиент и доступный HTTPS-туннель либо постоянный HTTPS-домен | Открытие Mini App |

На Windows/macOS можно использовать Docker Desktop, на Linux — Docker Engine
с плагином Compose либо Docker Desktop. Проверка: `docker compose version` и
`docker info`. На Windows Docker Desktop должен быть запущен в режиме Linux-контейнеров.

Первая сборка загружает образы и зависимости, установка моделей — веса размером
в несколько гигабайт. Нужны свободное место и память для модели 9B с контекстом 16384.
Практическая скорость зависит от оборудования; загрузка контейнеров сама по себе
не подтверждает, что модель успеет ответить за 60 секунд.

Каждый разработчик использует своего бота. Второй polling с тем же токеном мешает
уже запущенному экземпляру, а смена Mini App URL влияет на меню этого общего бота.

## Что не попадает в Git и как это восстановить

Для сборки достаточно отслеживаемых исходников: Dockerfile, Maven Wrapper,
`pom.xml`, `package-lock.json`, миграции, схемы и инструкции модели находятся в Git.

| Файл или каталог | Что нужно сделать на новом компьютере |
|---|---|
| `.env` | Скопировать `env.example`, заполнить свой токен, имя бота и HTTPS-адрес |
| Исходный `.backup` или ZIP с ним | Получить отдельно у команды; нужен только при самостоятельной подготовке корпуса или восстановлении исходной БД |
| `data/processed/<версия>/manifest.json`, `materials.jsonl`, `chunks.jsonl` | Получить три файла одной версии у команды **либо** создать из бэкапа по шагу 5; затем импортировать в Java |
| `data/source/` | Снимки и журналы создают инструменты; переносить рабочие логи и временные файлы не нужно |
| `data/source/local-runtime/` | Временные инструменты и диагностические файлы; для запуска не требуется |
| `frontend/node_modules/`, `frontend/dist/` | Docker устанавливает зависимости и собирает интерфейс; для разработки — `npm ci` и `npm run build` в `frontend/` |
| `backend/target/` | Docker собирает JAR из исходников |
| `.venv/`, `ml/.venv/`, `__pycache__/` | Создать окружение и установить `ml/requirements.lock`, только если выбран путь подготовки из бэкапа или работа с ML-прототипом |
| `.idea/`, `.DS_Store`, журналы и отчёты тестов | Для Docker-запуска не нужны; некоторые исходные настройки IDEA уже отслеживаются Git, но приложение от них не зависит |

Отдельно от файлов репозитория хранятся:

- **Веса Ollama.** Получаются командами `ollama pull` из шага 3. Они не включены в образы.
- **Том PostgreSQL.** На новом компьютере создаётся автоматически; Flyway создаёт
  структуру, импорт наполняет каталог. Профили, история, планы и напоминания будут
  новыми. Копия базы разработчика для проверки продукта не нужна.
- **HTTPS-туннель.** Запускается на компьютере с приложением по шагу 7.
  Полученный адрес указывается в настройках бота.

Минимальная внешняя поставка для полной работы — доступ к двум согласованным
моделям, свой токен бота и **либо пакет из трёх файлов, либо исходный бэкап**.
Реальные банковские данные остаются приватными. Если проверяющему не передан ни
пакет, ни бэкап, контейнеры запустятся, но содержательные консультации проверить нельзя.

## 2. Клонирование и настройки

```shell
git clone --branch main https://github.com/mkuzhvv/alfa-tg-botik.git
cd alfa-tg-botik
```

Windows PowerShell:

```powershell
Copy-Item env.example .env
```

macOS/Linux:

```bash
cp env.example .env
```

Редактируйте `.env` локально: одна строка `KEY=VALUE`, без `export` и кавычек.
Сначала оставьте `TELEGRAM_BOT_ENABLED=false`: так можно проверить контейнеры
без запуска приёма сообщений. Токен и HTTPS подключаются в шагах 6–7.

| Настройка | Назначение |
|---|---|
| `BACKEND_PORT=8080` | Порт Java на компьютере |
| `FRONTEND_PORT=8081` | Порт nginx/Mini App |
| `POSTGRES_PORT=5432` | Порт PostgreSQL на компьютере |
| `TELEGRAM_BOT_ENABLED=false` | Включение клиента Telegram и polling |
| `TELEGRAM_BOT_TOKEN=` | Токен собственного бота; нужен также для проверки входа Mini App |
| `TELEGRAM_BOT_USERNAME=alfa_business_helper_bot` | Имя собственного бота без `@`; попадает в сборку frontend |
| `TELEGRAM_MINI_APP_URL=` | Публичный HTTPS-адрес интерфейса |
| `DOCKER_OLLAMA_BASE_URL=http://host.docker.internal:11434` | Доступ Java-контейнера к Ollama на хосте |
| `ASSISTANT_MODEL=qwen3.5:9b-q4_K_M` | Локальная генеративная модель |
| `ASSISTANT_MODEL_REVISION=...` | Полный digest согласованных весов; значение есть в `env.example` |

Если порт занят, поменяйте соответствующий порт в `.env`. Внутренние адреса
`postgres:5432` и `backend:8080` менять не нужно. Дальнейшие примеры используют
стандартные порты. `.env` исключён из Git и Docker-образов.

## 3. Ollama и модели

Запустите приложение Ollama либо `ollama serve` в отдельном терминале.
Если сервер уже работает, второй экземпляр запускать не нужно.

```shell
ollama pull embeddinggemma:300m
ollama pull qwen3.5:9b-q4_K_M
ollama list
```

Ожидаемые digest весов:

| Модель | SHA-256 |
|---|---|
| `embeddinggemma:300m` | `85462619ee721b466c5927d109d4cb765861907d5417b9109caebc4e614679f1` |
| `qwen3.5:9b-q4_K_M` | `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90` |

Полные digest показывает локальный API `http://localhost:11434/api/tags`.
Если тег теперь указывает на другие веса, получите согласованные веса у ML-команды:
простая замена digest в `.env` не является подтверждением совместимости новой модели.
При изменении embedding-весов нужен новый индекс. Модели с суффиксом `:cloud` не подходят.

Проверка доступа именно из Java-контейнера после шага 4:

```shell
docker compose exec -T backend curl --fail --silent http://host.docker.internal:11434/api/tags
```

В Docker Desktop backend обращается к Ollama через `host.docker.internal`.
На Linux с Docker Engine loopback хоста недоступен из контейнера: Ollama должна
слушать интерфейс, доступный Docker-мосту. Для systemd настройка в
`sudo systemctl edit ollama.service`:

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
```

Затем `sudo systemctl daemon-reload` и `sudo systemctl restart ollama`.
Ограничьте доступ к порту 11434 локальным компьютером/Docker-мостом через firewall;
публиковать модель в интернет не требуется. При проблеме на macOS/Windows способ
задания `OLLAMA_HOST` описан в [официальном FAQ Ollama](https://docs.ollama.com/faq#how-do-i-configure-ollama-server).
Привязку и настройки VPN на чужом компьютере выбирает его владелец.

## 4. Первый запуск контейнеров

```shell
docker compose up -d --build --wait
docker compose ps
```

Ожидаются три сервиса `healthy`: `postgres`, `backend`, `frontend`.
Java/Flyway автоматически создаёт таблицы в новой `assistant`.
PostgreSQL при первой инициализации создаёт также пустую `alfa_source`.

Проверьте `http://localhost:8080/actuator/health`: ожидается `{"status":"UP"}`.
`http://localhost:8081/health` возвращает `ok`. Прямое открытие интерфейса в браузере
без Telegram покажет приглашение открыть приложение из бота.

**Здоровье контейнеров не означает готовность консультаций:** на этом шаге
каталог ещё пуст, а Telegram пока отключён.

## 5. Материалы: подготовка и импорт

В Git нет исходных банковских данных. Передайте их участнику отдельно по
согласованному командой каналу. Не добавляйте архивы, JSONL или дампы в коммиты.

### Вариант А: готовый пакет от ML/команды

Предпочтительный путь. Получите три файла одной версии и сохраните их так:

```text
data/processed/team-v1/manifest.json
data/processed/team-v1/materials.jsonl
data/processed/team-v1/chunks.jsonl
```

`team-v1` замените фактическим `datasetVersion` из manifest. Не переименовывайте
только каталог без согласования версии внутри файлов. Дополнительные отчёты
пакета могут остаться рядом. Python-индекс `semantic.sqlite` Java не использует.
Восстанавливать `alfa_source` для этого варианта не нужно.

### Вариант Б: есть только исходный бэкап

Нужен Python 3.11+. Используйте существующий инструмент ML в режиме подготовки
файлов: он не строит второй Python-индекс и не запускает чат.

Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ml/requirements.lock
.\.venv\Scripts\python.exe ml/setup_local.py "C:\path\alfa_course_hackathon.backup" --version team-v1 --data-only
```

macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r ml/requirements.lock
.venv/bin/python ml/setup_local.py "/path/to/alfa_course_hackathon.backup" --version team-v1 --data-only
```

В результате появляются локальный снимок в `data/source` и проверенный пакет в
`data/processed/team-v1`. Можно передать ZIP с бэкапом вместо самого `.backup`.
Для другого исходного файла выберите новую версию; существующие версии не перезаписываются.
Подробности ограничений импорта — в [ML README](../ml/README.md#данные-и-подготовка).

### Импорт пакета в Java

Одинаковые команды для PowerShell и Bash. Замените `team-v1` своей версией:

```shell
docker compose run --rm --no-deps -T backend java -jar /app/app.jar --spring.profiles.active=catalog-import --catalog.import-path=/data/processed/team-v1 --catalog.validate-only
docker compose run --rm --no-deps -T backend java -jar /app/app.jar --spring.profiles.active=catalog-import --catalog.import-path=/data/processed/team-v1
```

Первая команда проверяет файлы и контрольные суммы без индексации. Вторая через
локальную EmbeddingGemma строит векторы и сохраняет каталог в PostgreSQL.
Первый импорт может быть долгим: дождитесь `Catalog import completed` и кода выхода 0.
Профиль импорта отключает Telegram и веб-сервер; отдельный polling не появляется.

Для предоставленного исходного корпуса получены 1116 карточек, 3761 фрагмент
и 4877 векторов размерности 768. Другой разрешённый набор может иметь другие числа.
Повтор той же версии с теми же файлами/моделью использует готовый индекс.
При сбое прежний активный каталог сохраняется; обычный старт контейнеров импорт не запускает.

### Когда требуется восстановить исходную БД

`alfa_source` нужна для исследования SQL-структуры или выгрузки ML из PostgreSQL.
Рабочий Java-бот читает `assistant`, поэтому восстановление бэкапа и импорт каталога
не заменяют друг друга. Если нужен SQL-доступ к исходнику, выполните отдельно:

Windows:

```powershell
.\scripts\restore-source.ps1 -BackupPath "C:\path\alfa_course_hackathon.backup"
```

macOS/Linux:

```bash
bash scripts/restore-source.sh "/path/to/alfa_course_hackathon.backup"
```

PostgreSQL должен работать. Скрипты откажутся менять непустую `alfa_source`;
лог — `data/source/restore-source.log`. Локальные PostgreSQL-клиенты не нужны.
Сам `.backup` может лежать вне репозитория: скрипту передаётся его путь.

## 6. Включение бота

В официальном `@BotFather`: `/newbot` → название → уникальное имя с окончанием
`bot`. Сохраните токен в `.env`, укажите имя своего бота без `@`:

```dotenv
TELEGRAM_BOT_ENABLED=true
TELEGRAM_BOT_TOKEN=значение_из_BotFather
TELEGRAM_BOT_USERNAME=имя_своего_бота
```

```shell
docker compose up -d --no-deps --wait backend
docker compose up -d --build --no-deps --wait frontend
```

Пересборка frontend нужна при смене имени бота: это публичная настройка сборки.
После изменения `.env` используйте `up`, а не `restart`: именно пересоздание
контейнера применяет новое окружение. Дождитесь `Telegram polling started` в журнале.

Откройте своего бота и отправьте `/start`. Это создаёт пользователя и подтверждает
чат для доставки напоминаний. Затем задайте вопрос, например: «Что такое точка
безубыточности и зачем её считать?». Первый модельный ответ может быть медленнее
последующих из-за загрузки весов в память.

## 7. Mini App и HTTPS

Бот получает сообщения исходящими запросами к Telegram, поэтому для чата туннель
не нужен. Mini App открывает веб-страницу на компьютере пользователя и требует
доступный публичный HTTPS-адрес. `localhost:8081` на чужом телефоне ведёт к телефону,
а не к компьютеру разработчика.

Для временной проверки без регистрации запустите в отдельном терминале:

```shell
ssh -T -o IdentityAgent=none -o IdentitiesOnly=yes -o IdentityFile=none -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes -R 80:127.0.0.1:8081 nokey@localhost.run
```

Если меняли `FRONTEND_PORT`, замените 8081. При первом подключении SSH запросит
подтверждение ключа сервера. Возьмите последнюю выданную HTTPS-ссылку и укажите
её в `.env` как `TELEGRAM_MINI_APP_URL=https://выданный-адрес`.

```shell
docker compose up -d --no-deps --wait backend
```

Java зарегистрирует кнопку «Мой бизнес» в меню бота. Заново откройте чат и Mini App,
переключитесь между планом, календарём и профилем. Для меню достаточно этого
вызова API из Java; отдельная ручная настройка в BotFather не нужна.

SSH, контейнеры и компьютер должны оставаться включёнными. Бесплатный localhost.run
периодически меняет адрес, в том числе без переключения VPN. При `no tunnel`
проверьте последнюю ссылку в терминале, обновите `.env` и пересоздайте backend.
После смены адреса полностью закройте старое окно Mini App. Остановка туннеля — Ctrl+C.
Правила сервиса: [FAQ localhost.run](https://localhost.run/docs/faq).

Для туннеля требуется доступ к SSH и HTTPS. Постоянный домен и сервер
для непрерывной работы настраиваются отдельно.
Туннель направляется только в nginx: PostgreSQL и Ollama через него не публикуются.

## Повседневная работа

```shell
docker compose up -d --wait
docker compose ps
docker compose logs --tail 100 backend
docker compose stop
```

После изменения исходников: `docker compose up -d --build --wait`.
После изменения только `.env` бэкенда: `docker compose up -d --no-deps --wait backend`.
Модели и каталог повторно скачивать/индексировать не нужно, если их версии не менялись.

`stop` и `down` сохраняют именованный том PostgreSQL. **`down -v` удаляет данные**:
пользователей, историю, планы, напоминания и индекс. Для обычного перезапуска эта
команда не нужна. Исходники лежат в `data/source`, пакеты — в `data/processed`,
состояние приложения — в томе `alfa-tg-botik_postgres_data`, веса — в каталоге Ollama.

PostgreSQL использует `trust` без паролей по договорённости команды, опубликованные
порты привязаны к `127.0.0.1`. Этот Compose предназначен для локального стенда.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Docker недоступен | Запущен ли Docker Desktop/daemon, работают ли Linux-контейнеры |
| `port is already allocated` | Освободить порт либо изменить его в `.env` |
| Сборка не скачивает зависимости | Доступ Docker к registry/Maven/npm и настройки VPN/прокси |
| Контейнеры healthy, консультация не работает | Каталог импортирован, Ollama доступна из контейнера, обе модели установлены и digest совпадает |
| Модель не отвечает вовремя | Холодная загрузка, нехватка памяти, CPU вместо GPU; проверить `ollama ps` и журнал Ollama |
| Нет ответа бота / polling warnings | Сеть до Telegram, правильный токен и только один polling с этим токеном |
| Mini App не входит | Открыть из своего бота; совпадают ли токен backend и бот; проверить время компьютера |
| После рестарта требуется вход | Закрыть Mini App и открыть заново: сессии в памяти |
| HTTPS показывает `no tunnel` | SSH работает, используется последняя выданная ссылка, меню бота обновлено |
| Профиль/план изменён в другом месте | Нажать «Обновить данные» и повторить действие с актуальной версией |
| Напоминание не создаётся | Отправить `/start`, проверить будущую дату и IANA-зону, например `Europe/Moscow` |
| У завершённого напоминания нет кнопок | Это история доставки; редактирование/пауза/отмена доступны будущим отправкам |

Health проверяет Java и соединение с БД, но не готовность каталога, модели или
публичного туннеля. Сетевые предупреждения polling с автоматическим повтором
не равны падению Java; если они продолжаются и ответа нет, требуется восстановить сеть.

## Проверка работы

Подробный ручной маршрут с готовыми сообщениями и ожидаемыми результатами —
в [сценарии для проверяющего](DEMO.md). Его основной проход занимает примерно
10–15 минут на уже настроенном стенде; установка и первая индексация в это время не входят.

Короткая ручная проверка после настройки собственного стенда:

1. `/start` и `/help` отвечают; вопрос о бизнесе даёт ответ с источниками.
2. Явно сообщённая текущая задача видна в `/profile` и Mini App, изменение из Mini App — в чате.
3. План сохраняется после подтверждения; отметка шага видна и в чате, и в Mini App.
4. Разовое напоминание через несколько минут приходит; другое можно поставить на паузу и отменить.
5. После перезапуска backend профиль/план остаются, Mini App входит заново.

Для разработки и дополнительных команд смотрите [frontend README](../frontend/README.md),
[заметки по реализации](IMPLEMENTATION_NOTES.md) и [контракты](contracts/README.md).
